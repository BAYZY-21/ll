Q1 Definitions — Choose Two only تعريفات — اختر اثنين فقط
Note: The exam says "Choose Two only" — all three are answered below for complete study reference.
Definition 1
Internet of Things (IoT)
IoT is a network of physical objects (devices, sensors, machines, appliances) embedded with sensors, software, and connectivity that enables them to collect, exchange, and act on data over the internet — without requiring direct human interaction. The ultimate goal is automation and intelligent decision-making.
إنترنت الأشياء هو شبكة من الأجهزة المادية المزوّدة بمستشعرات وبرمجيات واتصال بالإنترنت، تمكّنها من جمع البيانات وتبادلها والتصرف بناءً عليها دون تدخل بشري مباشر. هدفه الأساسي هو الأتمتة واتخاذ القرارات الذكية.
Definition 2
Actuators (المحركات)
Actuators are hardware components that receive digital or electrical signals from a controller and convert them into physical actions in the real world. They are the "output" side of an IoT system — they make things happen physically based on decisions made by the system.

Examples: Electric motor (opens a valve), relay (switches a light on/off), servo motor (moves a robotic arm), buzzer (produces sound), LED (produces light).
المحركات هي مكونات مادية تستقبل إشارات رقمية أو كهربائية من وحدة التحكم وتحوّلها إلى أفعال فيزيائية في العالم الحقيقي. وهي الجانب "المُخرَج" في نظام IoT — تُنفّذ الإجراءات الفيزيائية بناءً على قرارات النظام.
أمثلة: المحرك الكهربائي (يفتح صمام)، المرحّل (يضيء مصباح)، المحرك السيرفو (يحرك ذراع روبوتية).
Definition 3
Perception Layer (طبقة الإدراك)
The Perception Layer is the first and lowest layer in the IoT 3-Layer Architecture. It is the physical foundation of any IoT system — responsible for interacting directly with the physical environment by collecting data through sensors and performing actions through actuators.

Key components: Sensors (temperature, humidity, ultrasonic, LDR), Actuators (motors, relays), Microcontrollers (Arduino, ESP32), RFID readers, Cameras.
طبقة الإدراك هي الطبقة الأولى والأدنى في معمارية IoT ذات الثلاث طبقات. إنها الأساس الفيزيائي لأي نظام IoT — مسؤولة عن التفاعل المباشر مع البيئة المادية عبر جمع البيانات بالمستشعرات وتنفيذ الأفعال بالمحركات.
المكونات: المستشعرات (حرارة، رطوبة، موجات فوق صوتية، LDR)، المحركات، وحدات التحكم الصغيرة (Arduino، ESP32)، كاميرات.

Question 3.1
Why is the ESP32 preferred over the Arduino Uno for IoT projects?
The ESP32 is the superior choice for IoT because:
  • Built-in Wi-Fi (2.4 GHz 802.11 b/g/n): No external shield needed — connects directly to the internet out of the box. Arduino Uno has no wireless capability.
  • Built-in Bluetooth (Classic + BLE): Enables direct device-to-device communication without extra hardware.
  • Dual-core 32-bit processor (240 MHz): Much faster than Arduino Uno's ATmega328P (8-bit, 16 MHz) — handles complex IoT tasks, JSON parsing, HTTPS requests in real time.
  • More memory: 520 KB RAM vs 2 KB on Arduino Uno — essential for network stacks and data processing.
  • More GPIO & peripherals: 34 GPIO pins, multiple SPI/I2C/UART interfaces, built-in ADC, DAC, Touch sensors.
  • Low power modes: Deep sleep draws only ~10 μA — critical for battery-powered IoT sensors.
يُفضَّل ESP32 على Arduino Uno في مشاريع إنترنت الأشياء لأنه يحتوي على: Wi-Fi وBluetooth مدمجَين (لا حاجة لدرع إضافي)، معالج ثنائي النواة 32-بت بسرعة 240 ميغاهرتز (أسرع بكثير من ATmega328P ذي 8-بت)، ذاكرة RAM تبلغ 520 كيلوبايت (مقابل 2 كيلوبايت فقط)، وأوضاع طاقة منخفضة جداً (Deep Sleep ~10 μA) مثالية للمستشعرات التي تعمل بالبطارية.
Question 3.2
Why is the Arduino IDE popular for both Arduino and ESP boards?
The Arduino IDE is popular for both board families because:
  • Unified environment: One IDE supports hundreds of boards — Arduino Uno, Mega, Nano AND ESP8266, ESP32 — via the Board Manager. Developers don't need to learn multiple tools.
  • Simple, beginner-friendly syntax: Based on C/C++ with simplified setup()/loop() structure — very low learning curve compared to raw MCU programming in assembly or bare C.
  • Massive library ecosystem: Thousands of free, community-maintained libraries (sensors, displays, protocols) work across all supported boards.
  • Serial Monitor: Built-in debugging tool to monitor data from both Arduino and ESP boards in real time.
  • Free & open source: No licensing cost — widely adopted in universities, hobbyist projects, and professional prototyping worldwide.
  • Active community: Millions of examples, tutorials, and forum answers available — shortens development time dramatically.
يحظى Arduino IDE بشعبية واسعة مع لوحات Arduino وESP لأنه: بيئة موحدة تدعم مئات اللوحات عبر مدير اللوحات، تستخدم بناء جملة C/C++ مبسطاً (setup/loop) سهل التعلم، تحتوي على آلاف المكتبات المجانية، وتأتي مع مراقب تسلسلي للتصحيح، وهي مجانية ومفتوحة المصدر مع مجتمع ضخم من المطورين والمتعلمين.

Q4.1
If you're looking for a web-like language that's highly agile and works in closed, resource-constrained environments, ___ is the smarter option.
a) HTTP
b) MQTT
c) TCP
d) CoAP
CoAP (Constrained Application Protocol) is a RESTful web-like protocol (GET/POST just like HTTP) but designed specifically for constrained/resource-limited IoT devices. It runs over UDP (not TCP) to reduce overhead. It's the "smart HTTP" for tiny devices.
Q4.2
A system reading sensors to perform an action but without internet access is called:
a) IoT System
b) Cloud System
c) Embedded System
d) Business System
An Embedded System performs specific tasks using sensors/actuators but has NO internet connectivity. When you add internet → it becomes an IoT system. Example: traditional microwave = embedded system; smart microwave with Wi-Fi = IoT system.
Q4.3
Which layer is responsible for routing and addressing data?
a) Sensing
b) Network
c) Application
d) Business
The Network Layer handles data transmission, routing, and addressing — it is the "bridge" that moves data from the Perception Layer to the Application Layer. Uses technologies like Wi-Fi, Zigbee, LoRaWAN, and protocols like IP, TCP/UDP.
Q4.4
Which protocol uses a Broker to manage messages?
a) HTTP
b) MQTT
c) CoAP
d) SPI
MQTT (Message Queuing Telemetry Transport) uses a Publish/Subscribe model with a central Broker server. Publishers send messages to the Broker by topic; the Broker distributes them to all matching subscribers. HTTP uses request/response; CoAP uses GET/POST; SPI is a hardware interface, not a messaging protocol.
Q4.5 (from image — MCQ continues)
The main processor chip on a standard Arduino Uno is:
a) ESP32
b) ATmega328P
c) ARM Cortex
d) Intel i7
The Arduino Uno uses the ATmega328P microcontroller (8-bit AVR, 16 MHz, 32 KB Flash, 2 KB RAM). ESP32 is used on ESP boards; ARM Cortex is used on Arduino Due/STM32; Intel i7 is a desktop CPU — not a microcontroller.
Q4.6
Which technology is the only option for remote surgery or self-driving cars due to its ultra-low latency?
a) Wi-Fi
b) LoRaWAN
c) Cellular (5G)
d) Zigbee
5G Cellular provides ultra-low latency (~1 ms), extremely high data rates, and wide-area coverage — the only technology capable of supporting time-critical applications like remote surgery and autonomous vehicles where any delay is dangerous. LoRaWAN is low-power but very slow; Wi-Fi has higher latency; Zigbee is short-range only.
Q4.7
A standard Arduino Uno has how many built-in Wi-Fi modules?
a) One
b) Two
c) Zero
d) Three
The standard Arduino Uno has ZERO built-in Wi-Fi. To add Wi-Fi you need an external module such as the ESP8266 (via AT commands or directly) or use an Arduino Uno WiFi Rev2 which has a built-in Wi-Fi chip. The ESP32/ESP8266 boards have Wi-Fi built in by default.

1 UART is a synchronous communication interface. FALSE
✎ UART stands for Universal Asynchronous Receiver-Transmitter. It does NOT use a shared clock signal — both devices agree on a baud rate (speed) instead. Synchronous interfaces (SPI, I2C) share a clock line. — التصحيح: UART هو واجهة تواصل غير متزامنة لا تستخدم خط ساعة مشترك.
2 Device-to-Device (D2D) communication requires the global internet to operate. FALSE
✎ D2D communication is local and direct — devices communicate with each other without needing the global internet. Common protocols: Bluetooth, Zigbee, Wi-Fi Direct. Example: smartwatch communicating directly with a phone. — التصحيح: D2D اتصال محلي مباشر بين الأجهزة دون الحاجة للإنترنت.
3 SPI communication uses a shared clock line (Synchronous). TRUE
4 The ESP32 microchip features a dual-core 32-bit processor. TRUE
5 CoAP is designed specifically to work over the UDP transport protocol to reduce overhead. TRUE
6 Cellular networks (like 5G) consume less power than LoRaWAN. FALSE
✎ Cellular 5G consumes significantly MORE power than LoRaWAN. LoRaWAN is designed for ultra-low power consumption — sensors can run for years on a small battery. 5G requires high power for continuous transmission at high data rates. — التصحيح: شبكات الخلوي 5G تستهلك طاقة أكثر بكثير من LoRaWAN. LoRaWAN مصمم لاستهلاك الحد الأدنى من الطاقة والعمل لسنوات بالبطارية.
7 The Arduino Nano has the exact same processing capabilities as the Arduino Uno but in a smaller size. TRUE
Note on Statement 7: Both Arduino Nano and Uno use the ATmega328P microcontroller running at 16 MHz with 32 KB Flash and 2 KB RAM — identical processing capabilities. The Nano is simply a smaller form factor (45×18 mm vs 69×53 mm) for compact project designs.

كلا اللوحتين (Nano وUno) تستخدمان نفس المعالج ATmega328P بنفس السرعة والذاكرة — الفرق الوحيد هو الحجم الأصغر للـ Nano.
